## Owner Decision

The release owner directed stable v6.2.0 publication from current `main` and
explicitly waived the remainder of the normal 72-hour soak after
`v6.2.0-rc.11`. This approval covers the current content cutoff and the final
metadata-only release-preparation commit.

This is a one-version owner-risk acceptance, not soak evidence and not a
standing exception for later releases. The changes after the RC11 tag must not
be described as RC-soaked. The workflow input `hotfix_exception=true` carries
this approved waiver through the existing promotion resolver; it does not
reclassify the stable minor release as a patch hotfix.

The exact pushed stable SHA must pass the no-publication `Release Dry Run` and
then be consumed unchanged by the normal single-build release workflow. The
rollback target remains stable `v6.1.2`, using the exact command recorded
above.

## Windows Signing Boundary

Exact-SHA dry run `31306697834` failed closed before candidate assembly or any
public mutation because SignPath reported the `release-signing` policy invalid;
its `Release certificate 2026` CSR remained pending. After that failure, the
release owner explicitly approved a `v6.2.0`-only unsigned-Windows exception so
the stable release can proceed while the external certificate request remains
unavailable.

This is a separate, version-bound decision and is not implied by the soak
waiver. Windows artifacts must remain bound to the exact source SHA and
candidate manifest, checksums, detached `.sig`/`.sshsig` signatures, and
published-digest verification. Public release notes must disclose that the
Windows binaries are not Authenticode-signed and may display an Unknown
Publisher warning. Stable `v6.2.1` and later restore mandatory Authenticode
signing unless another explicit version-bound owner decision is recorded.

The two-strike release-task stop rule applies. No third release rehearsal,
test-threshold change, tag, draft, or public release was made. The harness work
is tracked under lane follow-up `performance-post-rc-headroom` and must proceed
as a separately claimed test-stabilization slice before a fresh exact-SHA
release rehearsal.

## Performance Harness Remediation

The separately claimed performance-harness slice found that the fixed-duration
800-request quota compared current Go 1.26 / SQLite-driver behavior with a
request count recorded under an earlier toolchain and made hosted-runner CPU
and filesystem speed part of the release verdict. The corrected proof executes
fixed concurrent work and compares its throughput with a serial baseline from
the same process, while retaining the absolute concurrent p95 ceiling. The
load fixture now also waits for deferred metrics-store startup maintenance.
The fast single-request store SLO uses small amortized batches to reject
sustained latency regressions without allowing isolated scheduler or GC pauses
to decide the release.

Five consecutive strict `GITHUB_ACTIONS=true` repetitions passed locally.
Concurrency efficiency held at 1.39-1.42x the same-run serial baseline,
concurrent p95 held at 0.97-1.30s against the unchanged 8s ceiling, and the
store-backed SLO p95 held at 7.60-7.84ms against 12ms. Publication still
requires a fresh no-publication rehearsal on the final pushed exact SHA.

Exact-SHA dry run `31320692142` on
`53d9d00d8d478d537e12aa496533900acafe3bbc` passed native policy, macOS
signing and notarization, and complete immutable-candidate validation. Its
backend job exposed two remaining wall-clock harness assumptions:
`TestLoad_500Node_MixedEndpoints` completed seven metrics-stats requests
against a fixed-window minimum of ten, and `TestSLO_MetricsHistoryStore`
sustained an 11.980ms median with a 12.230ms p95 against the 12ms hosted
ceiling. The mixed test now executes fixed work per endpoint group and keeps
the absolute p95 budgets as its contention regression guard. The strict local
store target remains 5ms; the hosted-runner envelope is narrowly recalibrated
to 15ms so the observed public-runner baseline retains measurable headroom
without allowing a material endpoint or SQLite-query regression. A new pushed
exact SHA and fresh no-publication rehearsal are required.

Three consecutive focused `GITHUB_ACTIONS=true` repetitions passed after the
follow-up. Each mixed-load repetition completed exactly 60 resource, 50
metrics-history, and 10 metrics-stats requests with zero errors; mixed
wall-clock time held at 0.838-0.846s, metrics-history p95 at 0.702-0.748s, and
metrics-stats p95 at 0.454-0.633s. The store-backed SLO p95 held at
7.58-7.60ms against the 15ms hosted envelope. A complete
`GITHUB_ACTIONS=true go test -p 1 ./internal/api -count=1` package-order proof
also passed in 153.837s.
