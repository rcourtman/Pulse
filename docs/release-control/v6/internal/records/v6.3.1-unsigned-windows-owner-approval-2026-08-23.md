# v6.3.1 Unsigned Windows Owner Approval

- Decision date: `2026-08-23`
- Release: `v6.3.1`
- Promotion path: emergency stable patch from `main`
- Rollback target: `v6.3.0`
- Exact rollback reinstall command: `./scripts/install.sh --version v6.3.0`
- Failed signing rehearsal: `32634435531`

## Owner Decision

Exact-SHA rehearsal `32634435531` reached the SignPath production
`release-signing` policy after the GitHub-hosted provenance correction. SignPath
rejected the request because the SignPath production certificate remains `CSR PENDING`,
which leaves the production policy invalid. The SignPath project, repository,
branch, build definitions, submitter, and approval configuration are present;
certificate issuance is not an owner-actionable step in the SignPath workspace.

On 2026-08-23, the release owner explicitly authorized unsigned Windows Unified
Agent artifacts for stable `v6.3.1` so the externally pending certificate does
not block the otherwise qualified emergency patch.

This is a version-bound risk acceptance, not evidence that Authenticode
succeeded and not a standing exception for later releases. Stable `v6.3.2` and
later restore mandatory Authenticode unless a new explicit, version-bound owner
decision is recorded.

## Required Integrity Controls

The exception changes only the Authenticode requirement. Windows artifacts must
still be built from the exact release SHA and bound to the immutable candidate
manifest, SHA-256 checksums, detached `.sig` and `.sshsig` signatures, and
published-digest verification. The public release notes state that the Windows
binaries are not Authenticode-signed and may display an Unknown Publisher
warning.

The normal integrated frontend, backend, installer, Docker, Helm, macOS signing
and notarization, candidate validation, publication, activation, and convergence
controls remain unchanged.
