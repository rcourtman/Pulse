## Customer-Surface Convergence

The first convergence attempt failed before acquiring the global promotion
lease. The activation marker was uploaded at `2026-08-23T12:56:19Z`, but its
public download edge returned HTTP 404 through `2026-08-23T12:56:32Z`. The
source release run completed during that propagation window, and the waiter
incorrectly treated completion as proof that the uploaded marker could not
become readable. Docker aliases, Helm Pages, the paid-runtime broker, and the
stable demo were all skipped, so the failed attempt did not mutate any of
those surfaces.

Attempt 2 adopted the immutable marker from the completed original owner and
passed:

- global customer-promotion lease acquisition and release;
- Docker server and control-plane stable-alias promotion;
- public Helm Pages publication and verification;
- private paid-runtime broker promotion and live verification;
- stable-demo update to `6.3.1`, runtime and frontend parity, public health,
  and browser smoke; and
- `Customer Promotion Convergence Verdict`.

Direct registry inspection after convergence confirmed that both
`ghcr.io/rcourtman/pulse:latest` and
`ghcr.io/rcourtman/pulse-control-plane:latest` resolve to the same manifest
digests as their respective `v6.3.1` tags.

## Workflow Corrections

Stable release runner selection is now channel-based across the public and
private Pro build paths. Stable preparation, frontend bundling, backend tests,
public exact-SHA compilation, container/Helm qualification, and private Pro
compilation use GitHub-hosted runners even when a version-bound Windows-signing
exception applies. Explicit prereleases retain credential-free PVE
acceleration.

The convergence waiter now distinguishes an absent activation marker from an
uploaded marker awaiting public edge propagation. A completed unsuccessful
source run or a successful source run without an uploaded marker still fails
promptly. An uploaded exact-name marker receives a bounded public-propagation
grace, while a readable marker with the wrong immutable identity fails
immediately.

## Windows Exception

Windows Unified Agent and MCP artifacts for `v6.3.1` are not
Authenticode-signed and may display an Unknown Publisher warning. This is the
version-bound owner exception recorded in
`v6.3.1-unsigned-windows-owner-approval-2026-08-23.md`; exact-SHA builds,
SHA-256 checksums, detached signatures, immutable-manifest validation, and
published-digest verification remained mandatory and passed. Stable `v6.3.2`
and later require Authenticode unless another explicit version-bound exception
is recorded.
